# Ollama Chat interface fields

## Protocol Identity

- Plugin ID: `ollama-chat`.
- Provider ID: `ollama-chat`.
- Abilities: `text`.
-Default Base URL: `http://127.0.0.1:11434`.
- Authentication driver: `none`.
- Create: `POST /api/chat`.
- Life cycle: synchronous response.

## Configuration fields

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `apiKey` | secret | No | API Key. Ollama has no authentication by default and can be left blank. |

## Unified field mapping

| Uniform Fields | Type | Required | Upstream Mapping | Description |
| --- | --- | --- | --- | --- |
| `model` | string | Yes | `model` | Upstream model ID. |
| `messages` | message[] | Yes | `provider message container` | Contains historical messages and current user input. |
| `instructions` | string | No | `system/instructions` | System command. |
| `temperature` | number | No | `temperature` | Sampling temperature. |
| `top_p` | number | No | `top_p` | Kernel sampling parameters. |
| `max_tokens` | integer | No | `max_tokens/max_output_tokens` | Maximum output token. |
| `tools` | array | No | `tools/toolConfig` | Tool definition. |
| `tool_choice` | object|string | No | `tool_choice` | Tool selection strategy. |
| `response_format` | object | No | `response_format/text` | Structured output configuration. |
| `stream` | boolean | No | `stream` | Streaming switch; background tasks are currently normalized to the final response. |

## Provider extension key

- `providerOptions.ollama-chat.format`
- `providerOptions.ollama-chat.keep_alive`
- `providerOptions.ollama-chat.options`
- `providerOptions.ollama-chat.think`
- `providerOptions.ollama-chat.tools`

Dynamic models or workflows are allowed to use the complete `parameters/input/extra_body` object declared by the document; this object is the open schema of the protocol itself and will not be tailored by the host.

## Response mapping field-by-field list

| Mapping location | Upstream path or transformation expression |
| --- | --- |
| `response.status` | `"succeeded"` |
| `response.textPaths[0]` | `"message.content"` |
| `response.textPaths[1]` | `"response"` |
| `response.reasoningPaths[0]` | `"message.thinking"` |
| `response.reasoningPaths[1]` | `"thinking"` |
| `response.errorPaths[0]` | `"error"` |
| `response.messagePaths[0]` | `"error"` |

## Responses and Errors

The plug-in maps the upstream task/status/text/media/usage to a unified result. Ephemeral media URLs are marked as ephemeral and are immediately downloaded for persistence by the host. HTTP errors, business code and error objects maintain failure semantics and are not packaged as success.

## Compatibility boundary

This package only represents the above line protocol profile; other endpoint, cloud zone or gateway packages of the same brand must use independent plug-ins and cannot be guessed based on the model name.
