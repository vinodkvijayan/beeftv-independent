# OpenAI Videos / Sora interface fields

> Official service status: OpenAI has closed the Sora 2 model and Videos API on 2026-09-24, and there is no one-to-one replacement interface; official documents are retained for historical records only.
> This protocol is therefore only available on third-party relays that still provide the `/v1/videos` contract with the same name. Directly generating videos with ordinary OpenAI Keys is not guaranteed to be available. Keeping them as they are is to not interrupt these transits and does not mean that the official links are still in service.

This protocol sends at most one reference picture, and does not send reference video, reference audio, last frame or mask. When the protocol capabilities are exceeded, an error will be reported before submission, and the material will not be silently ignored. For the multi-image video interface of a third-party service, please select the corresponding JSON or native protocol according to its documentation.

## Protocol Identity

- Plugin ID: `openai-videos`.
- Provider ID: `newapi`.
- Abilities: `video`.
-Default Base URL: `https://api.openai.com`.
- Authentication driver: `bearer`.
- Create: `POST /v1/videos`.
- Query: `GET /v1/videos/{{taskId}}`.
- Cancellation: `DELETE /v1/videos/{{taskId}}`.

## Provider extension key

- `providerOptions.newapi.variants`

Dynamic models or workflows are allowed to use the complete `parameters/input/extra_body` object declared by the document; this object is the open schema of the protocol itself and will not be tailored by the host.

## Response mapping field-by-field list

| Mapping location | Upstream path or transformation expression |
| --- | --- |
| `response.taskId` | `{"$coalesce":[{"$ref":"response.id"},{"$ref":"response.task_id"},{"$ref":"response.taskId"},{"$ref":"response.data.id"},{"$ref":"taskId"}]}` |
| `response.status` | `{"$coalesce":[{"$ref":"response.status"},{"$ref":"response.state"},{"$ref":"response.data.status"},"pending"]}` |
| `response.message` | `{"$coalesce":[{"$ref":"response.error.message"},{"$ref":"response.message"},{"$ref":"response.fail_reason"}]}` |
| `response.videos` | `{"$coalesce":[{"$ref":"response.url"},{"$ref":"response.video_url"},{"$ref":"response.output.url"}]}` |
| `response.errorPaths[0]` | `"error.code"` |
| `response.resultEphemeral` | `true` |
| `response.messagePaths[0]` | `"error.message"` |

## Responses and Errors

The plug-in maps the upstream task/status/text/media/usage to a unified result. Ephemeral media URLs are marked as ephemeral and are immediately downloaded for persistence by the host. HTTP errors, business code and error objects maintain failure semantics and are not packaged as success.

## Compatibility boundary

This package only represents the above line protocol profile; other endpoint, cloud zone or gateway packages of the same brand must use independent plug-ins and cannot be guessed based on the model name.
