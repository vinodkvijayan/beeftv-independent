# OpenAI Audio Speech interface fields

## Protocol Identity

- Plugin ID: `openai-audio`.
- Provider ID: `openai-audio`.
- Abilities: `audio`.
-Default Base URL: `https://api.openai.com`.
- Authentication driver: `bearer`.
- Create: `POST /v1/audio/speech`.
- Life cycle: synchronous response.

## Configuration fields

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `apiKey` | secret | Yes | API Key |

## Unified field mapping

| Uniform Fields | Type | Required | Upstream Mapping | Description |
| --- | --- | --- | --- | --- |
| `model` | string | Yes | `model` | Audio model ID. |
| `prompt` | string | Yes | `input` | Text to be synthesized. |
| `providerOptions` | object | No | `provider-specific fields` | Vendor extension field within the plugin namespace. |

## Provider extension key

- `providerOptions.openai-audio.instructions`
- `providerOptions.openai-audio.response_format`
- `providerOptions.openai-audio.speed`
- `providerOptions.openai-audio.voice`

Dynamic models or workflows are allowed to use the complete `parameters/input/extra_body` object declared by the document; this object is the open schema of the protocol itself and will not be tailored by the host.

## Response mapping field-by-field list

| Mapping location | Upstream path or transformation expression |
| --- | --- |
| `response.binaryPayload` | `true` |
| `response.resultKind` | `"audio"` |
| `response.status` | `"succeeded"` |
| `response.errorPaths[0]` | `"error.code"` |
| `response.messagePaths[0]` | `"error.message"` |

## Responses and Errors

The plug-in maps the upstream task/status/text/media/usage to a unified result. Ephemeral media URLs are marked as ephemeral and are immediately downloaded for persistence by the host. HTTP errors, business code and error objects maintain failure semantics and are not packaged as success.

## Compatibility boundary

Synchronizing /v1/audio/speech returns the raw audio stream, wrapped by binaryPayload into a unified audio result.

When MiniMax Music is generated through the enterprise interface, the output is fixed to MP3, defaulting to 44.1 kHz, 256 kbps. Slower build requests use SSE heartbeats to wait for results; the task does not succeed until a completion event is received and valid audio is obtained. Interrupts, error events, or non-audio responses are handled as failures and do not automatically regenerate.
