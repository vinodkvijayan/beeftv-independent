# Luma Dream Machine interface fields

## Protocol Identity

- Plugin ID: `luma-dream-machine`.
- Provider ID: `luma-dream-machine`.
- Abilities: `video`.
-Default Base URL: `https://api.lumalabs.ai`.
- Authentication driver: `bearer`.
- Create: `POST /dream-machine/v1/generations`.
- Query: `GET /dream-machine/v1/generations/{{taskId}}`.
- Path splicing: The official path itself already contains `/dream-machine/v1`. Both operations are replaced by the root path (`originPath`). The host will no longer supplement the `/v1` prefix; otherwise, `/v1/dream-machine/...` will be requested. For this reason, the service address should be filled in with the host root address (default `https://api.lumalabs.ai`); if the relay is hung in a sub-path, it needs to be able to respond directly to `/dream-machine/v1/generations`.
- Status: Official `state` takes `queued` / `dreaming` / `completed` / `failed`, among which `dreaming` is mapped as processing.
- Result: Official `assets.video`.
- Old receipt compatibility: continue to read `video_url`, `videoUrl`, `result_url`, `url`, `data.video_url`, `output.url`; error message remains `fail_reason`.

## Provider extension key

- `providerOptions.luma-dream-machine.body`
- `providerOptions.luma-dream-machine.extra_body`

`body` / `extra_body` will be merged into the creation request body and overwrite the official fields with the same name. They are used for third-party transfers that still provide the same name interface but require additional fields; the host does not trim the content.

## Responses and Errors

The plug-in maps the upstream task/status/text/media/usage to a unified result. Ephemeral media URLs are marked as ephemeral and are immediately downloaded for persistence by the host. HTTP errors, business code and error objects maintain failure semantics and are not packaged as success.

## Compatibility boundary

This profile corresponds to `POST /dream-machine/v1/generations` and `GET /dream-machine/v1/generations/{id}` of Dream Machine API. The creation request is sent according to the official fields `model`, `prompt`, `aspect_ratio`, `resolution`, `duration` and `keyframes`: `duration` is written as the officially required string (such as `5s`; the official schema allows any string, the common value is `5s` / `9s`), `resolution` is uniformly lowercase, 2160p is converted to the official writing `4k`, the first frame and the last frame are written as `keyframes.frame0` / `frame1` `image` type; character or style reference pictures, reference videos, and reference audios will report an error before submission and will not be silently discarded. The official document writes the online image address as the only delivery method, so this profile declares `requiresPublicMediaUrls: true` and `mediaTransport.image` as `url`: the local image is uploaded to the object storage by the host first and replaced with an online address. If the online address cannot be obtained, `reference_media_requires_url` is returned before submission. The data URL will not be written into `keyframes.frame0.url` / `frame1.url` which only accepts online addresses. Results retrieved from official `assets.video`.
