# Runway Video interface fields

## Protocol Identity

- Plugin ID: `runway-video`.
- Provider ID: `runway-video`.
- Abilities: `video`.
-Default Base URL: `https://api.dev.runwayml.com`.
- Authentication driver: `bearer`.
- Create: `POST /v1/image_to_video` when there is the first frame, `POST /v1/text_to_video` when there is plain text.
- Query: `GET /v1/tasks/{{taskId}}`.
- Request header: `X-Runway-Version: 2024-11-06` with official requirements for creation and query; requests missing this header will be rejected by the upstream.

## Configuration fields

Old receipt compatibility: continue reading `video_url`, `videoUrl`, `result_url`, `url`, `data.video_url`, and `output.url`, then read official `output[]`. `output` objects with only status information cannot block video addresses in other fields; when these fields have no addresses, no media results are generated.

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `apiKey` | secret | Yes | API Key |

| 统一字段 | 类型 | 必填 | 上游映射 | 说明 |
| --- | --- | --- | --- | --- |
| `model` | string | 是 | `model` | 视频模型 ID。 |
| `prompt` | string | 是 | `promptText` | 视频提示词。 |
| `images` | media[] | 否 | `promptImage（first / last）` | 首帧是所有图生视频模型的入口；尾帧只在官方明确限制为单帧的模型上被拦（`gen4.5`、`gen4_turbo`、`happyhorse_1_0`、`gemini_omni_flash`、`grok_imagine_1_5`、`grok_imagine_1_5_lite`），`veo3.1`、`kling2.5_turbo_pro`、`seedance2_5`、`h3_max` 等照常发送。其它角色在提交前报错。 |
| `duration` | integer | 否 | `duration` | 时长秒数，取值区间由所选模型决定。 |

## Provider extension key

- `providerOptions.runway-video.body`
- `providerOptions.runway-video.extra_body`

`body` / `extra_body` will be merged into the creation request body and overwrite the official fields with the same name. They are used for third-party transfers that still provide the same name interface but require additional fields; the host does not trim the content.

## Responses and Errors

The plug-in maps the upstream task/status/text/media/usage to a unified result. Ephemeral media URLs are marked as ephemeral and are immediately downloaded for persistence by the host. HTTP errors, business code and error objects maintain failure semantics and are not packaged as success.

## Compatibility boundary

The request body of this protocol is a discriminant union differentiated by `model`: the optional pixel ratio of `ratio`, the value range of `duration`, and the upper limit of the prompt word length all change with the model. The plug-in only fixes the line protocol entry and unified fields, and sends `promptText`, `promptImage`, `ratio`, `duration` according to the official fields: `aspectRatio` First convert to the official pixel ratio (16:9→1280:720, 9:16→720:1280, 1:1→960:960, 4:3→1104:832, 3:4→832:1104, 21:9→1584:672). If it cannot be converted, send it as it is; the first frame and the last frame are written as `promptImage` `first` / `last` location. The official `POST /v1/image_to_video` is a discriminant combination differentiated by `model`. The `promptImage` capabilities of each model are different: `position` of `gen4.5`, `gen4_turbo`, `happyhorse_1_0`, `gemini_omni_flash`, `grok_imagine_1_5`, `grok_imagine_1_5_lite` only has `first`, while `position: last` is accepted for `veo3.1` / `veo3.1_fast`, `kling2.5_turbo_pro`, `kling3.0_pro` / `kling3.0_standard`, `seedance2` series, `seedance2_5`, `h3_max`, `kling_4`, `hailuo3`, `wan3` series, etc. Therefore, the verification only blocks single-frame models that are explicitly restricted by the official. The other models (including new models and transits that still forward the interface with the same name) are sent as they are and handed over to the upstream for judgment. Legal tail frames will not be rejected because the local list has not kept up. Character or style reference pictures, reference videos, and reference audios will also report an error before submission and will not be silently discarded. The resolution is determined by `ratio`: This profile does not deliver the resolution level of the host (`resolution`). Selecting 480p or 1080p will not change the request. The output level is based on `ratio`. Some models also have a `resolution` field, or only accept a specific pixel ratio (for example, a few 4K models only accept `3840:2160`), which can be overwritten with `providerOptions.runway-video.body` when needed. After the task is successful, retrieve the video address from the official `output[]`. When the corresponding authentication driver is not configured, the cloud signature type entry will explicitly fail and will not pretend to be a Bearer success.

Field correspondence and fixed success examples are transplanted from the MIT part of LiteLLM (`litellm/llms/runwayml/videos/transformation.py` and its single test, submit `dddbaa803d6e9fcc862ea7a5412f771cb1ae040e`). The complete MIT statement is distributed with this plug-in package, see `LICENSE` in the plug-in directory (`THIRD_PARTY_NOTICES.md` in the warehouse root directory records the same statement); here it is only rewritten as a declarative template and Go test, and the Python runtime is not introduced.
